# 맞고 게임 개발 요청사항

AI와 1:1로 두는 고스톱(맞고) 웹 게임을 만들기 위한 요구사항 문서입니다.
이 저장소의 게임을 만들며 실제로 요청하고 결정한 내용을 정리했습니다. 문서를 그대로 AI 코딩 도우미(예: Claude Code)에게 주거나, 원하는 부분을 고쳐 **자기만의 맞고 게임**을 만드는 데 쓰세요.

- 🔧 표시는 취향에 따라 바꿔도 되는 **하우스 룰·설정값**입니다. 바꾸면 관련 테스트와 문서도 함께 바꾸도록 요청하세요.
- 규칙 조사 결과와 세부 판정 기준은 [RULES.md](RULES.md)에 더 자세히 있습니다.
- 이 저장소의 코드와 문서는 AI(Claude)가 작성했습니다. 이 문서로 만드는 결과물도 AI가 작성한 코드에는 검토되지 않은 오류가 있을 수 있음을 전제로 확인하며 진행하세요.

---

## 1. 목표와 범위

- 브라우저에서 바로 실행되는 **맞고(2인 고스톱)**. 플레이어(나) 1명과 AI 1명이 둡니다.
- 서버 없이 동작합니다. 개발 서버, 빌드 결과 파일 더블클릭(`file://`), 블로그 글 삽입 세 가지 방식으로 실행할 수 있어야 합니다.
- 쉬려고 하는 게임이므로 **플레이어를 돕는 수 추천**을 제공하되, 추천은 공개된 정보만 씁니다.
- 진행 상황(돈, 레벨, 전적)은 자동 저장되어 다음 실행 때 이어집니다.

## 2. 기술 스택

| 분류 | 요구 |
|---|---|
| 언어 | TypeScript (strict, 사용하지 않는 변수 금지) |
| 빌드 | Vite. 빌드 결과는 **상대 경로 + 일반 스크립트(IIFE)** 로 만들어 `dist/index.html`을 더블클릭해도 동작해야 함 (`file://`에서는 `type="module"`과 `crossorigin`이 막힘) |
| 테스트 | Vitest |
| UI | 프레임워크 없이 DOM API 직접 사용 |
| 애니메이션 | Web Animations API로 FLIP(이전 위치 → 새 위치) 애니메이션 |
| 사운드 | Web Audio API로 효과음 합성 (음원 파일 없음). 첫 클릭 때 오디오 잠금 해제, 소리 켜기/끄기 저장 |
| 저장 | 브라우저 localStorage (`try/catch`로 감싸고, 저장소가 없어도 게임은 동작) |
| 카드 그림 | SVG |

구조는 **규칙 엔진(순수 함수)** 과 **화면**을 분리합니다.
- 엔진: `step(상태, 행동) → 프레임[]`. 각 프레임은 `{ 상태 스냅숏, 이벤트[] }`이고, 화면은 프레임을 차례로 재생하며 애니메이션과 소리를 냅니다.
- 상태 단계: `play`(낼 패 고르기) → `chooseFloor`(바닥 2장 중 고르기) → `gukjin`(국진 전환) → `goStop` → `end`.

## 3. 화투 구성

- 기본 48장 + **보너스패 2장** = 50장. 🔧
  - 보너스 2피 1장, 보너스 3피 1장
  - 빨간 바탕에 큰 숫자 `2`/`3`을 가운데 그린 디자인. 11월·12월 기본 쌍피는 일반 디자인 그대로
- 9월 열끗(국진, 술잔)은 열끗 또는 쌍피로 쓸 수 있습니다(9절 참고).
- 카드 번호: `(월 - 1) × 4 + 월 안의 순서`, 보너스패는 48·49번.

## 4. 진행 규칙

- 각자 10장, 바닥 8장, 나머지는 더미(뒷패). 바닥에 같은 월 4장이 깔리면 다시 나눕니다.
- 바닥에 깔린 보너스패는 선이 가져가고 더미에서 1장 보충합니다.
- 손에 같은 월 4장이면 **총통**: 즉시 10점 승리. 🔧
- 한 턴: 손패 1장 내기 → (바닥 2장 중 고르기) → 더미 1장 뒤집기 → (바닥 2장 중 고르기) → 특수 상황 처리 → 점수 확인.
- 먼저 7점 이상이면 **고**(계속) 또는 **스톱**(정산). 고 이후에는 지난 고 점수보다 1점 이상 올라야 다시 고/스톱을 고를 수 있습니다.
- 더미나 손패가 다 떨어진 상태에서 7점에 닿으면 자동 스톱합니다.
- 둘 다 스톱하지 못하고 패가 다 떨어지면 **나가리**(무승부).

### 특수 상황

| 상황 | 처리 |
|---|---|
| 쪽 | 짝 없이 낸 패를 뒤집은 패로 먹음 → 상대 피 1장 |
| 따닥 | 바닥 2장과 낸 패·뒤집은 패가 모두 같은 월 → 4장 획득 + 상대 피 1장 |
| 뻑 | 낸 패로 바닥 1장과 짝지었는데 뒤집은 패도 같은 월 → 3장이 바닥에 남음 |
| 뻑 먹기 | 바닥의 같은 월 3장을 4번째 패로 먹음 → 상대 피 1장. 🔧 **처음 배분 때 깔린 3장을 먹을 때도 같은 규칙** |
| 자뻑 | 자기가 싼 뻑을 자기가 먹음 → 상대 피 2장 |
| 첫뻑 🔧 | 각자의 **첫 턴**에 뻑이 나면 상대에게서 **7점 × 점당 금액**을 즉시 받음 (판의 승패·배수와 별개) |
| 삼연뻑 | 3연속 뻑 → 즉시 10점 승리 🔧 |
| 쓸(싹쓸이) | 바닥을 모두 쓸어 감 → 상대 피 1장 (마지막 턴 제외) |
| 흔들기 | 손에 같은 월 3장, 바닥에 그 월 없음 → 3장을 보여 주고 1장 냄. 이기면 ×2 |
| 폭탄 | 손 3장 + 바닥 1장이면 3장을 한 번에 내서 4장 획득 + 상대 피 1장, ×2, 빈 패 2장. 🔧 **손 2장 + 바닥 2장도 폭탄**(빈 패 1장) |
| 보너스패 🔧 | 내거나 뒤집어 가져오면 **상대 피 1장을 빼앗고**, 손에서 냈으면 더미에서 1장 받아 한 장 더 냄 |

- 피를 빼앗을 때 순서: 일반 피 → 쌍피(쌍피로 전환한 국진 포함) → 보너스 2피 → 보너스 3피. 일반 피가 없으면 쌍피·3피를 그대로 가져옵니다.

## 5. 점수와 정산

| 항목 | 점수 |
|---|---|
| 광 | 3광 3점(비광 포함 2점), 4광 4점, 5광 15점 |
| 열끗 | 5장 1점, 이후 1장마다 +1. 고도리(2·4·8월 새) 5점 |
| 띠 | 5장 1점, 이후 1장마다 +1. 홍단·청단·초단 각 3점 |
| 피 | 10장 1점, 이후 1장마다 +1 (쌍피 2장, 보너스 2피 2장, 3피 3장) |

- 고 보너스: 1고 +1점, 2고 +2점, 3고부터 (점수 + 고 횟수) × 2^(고 횟수 − 2).
- 배수(모두 곱함): 흔들기 ×2(횟수만큼), 폭탄 ×2(횟수만큼), 피박 ×2(진 쪽 피 7장 미만), 광박 ×2(진 쪽 광 0장), 멍박 ×2(이긴 쪽 열끗 7장 이상), 고박 ×2(진 쪽이 고를 했음), 나가리 배수.
- 진 쪽의 피박 판정에서는 국진을 피로 세어 줍니다.

## 6. 돈·레벨·AI 상대 (하우스 룰)

- 플레이어 시작 금액 **50,000원**. 🔧
- **점당 금액 = (floor(레벨 ÷ 5) + 1) × 100원** (레벨 1~4: 100원, 5~9: 200원, 10~14: 300원 …). 🔧
- 스톱으로 승패가 나면 **이긴 쪽 최종 점수 × 점당 금액**을 진 쪽이 줍니다. 가진 돈이 모자라면 있는 만큼만.
- **나가리**: 다음 판 최종 점수 ×2. 연속이면 누적(×2, ×4, ×8 …). 🔧
- **AI 생성**: 새 게임 시작 또는 AI 파산 때 새 AI가 나옵니다. 이름은 무작위(예: "눈치 빠른 부엉이").
  - 첫 AI: 50,000원
  - 다음 AI: **이전 AI의 시작 금액 × (1 + 0~40% 무작위)**, 100원 단위 반올림 🔧
- **레벨**: 1에서 시작, AI가 파산할 때마다 +1.
- **플레이어 파산**: 게임 오버, 완전 초기화.
- 판 도중 지급(첫뻑)으로 돈이 바닥난 쪽은 판이 끝날 때(나가리여도) 파산 처리합니다.

## 7. 자동 저장

- 판이 끝날 때마다 저장: 양쪽 돈, 레벨, 현재 AI(이름·돈·시작 금액), 다음 판 선, 연속 나가리 수, 전적.
- 판을 시작할 때 "진행 중" 표시를 저장합니다. 판을 끝내지 않고 나가면(새로고침, 창 닫기) 다음 실행 때 **기권패(7점)** 로 처리하고 알려 줍니다. 🔧

## 8. AI 상대

- 내 수마다 더미에서 나올 수 있는 모든 모르는 패를 하나씩 가정해 결과를 평균 내고, 가장 좋은 수를 고릅니다.
- 평가 = 내 획득 패 가치 − 0.9 × 상대 획득 패 가치 − 바닥에 남긴 패를 상대가 가져갈 위험.
- 획득 패 가치(`potential`)는 점수 × 3에 족보 진행도와 장수 진행도를 더합니다. **장수 진행 가치는 기준 장수(피 10장, 열끗·띠 5장)에 닿은 뒤에도 유지**해야 합니다. 사라지면 10장째 피가 오히려 손해로 계산되는 버그가 생깁니다.
- 고/스톱: 더미가 적거나 상대 점수가 높으면 스톱.
- AI는 **상대 손패와 더미 순서를 보면 안 됩니다**(공정성).
- 검증: AI 대 단순 탐욕 정책 시뮬레이션에서 AI가 더 많이 이겨야 합니다.

## 9. 국진(9월 술잔) 전환

- 기본은 **열끗**으로 계산하고 열끗 묶음에 둡니다.
- 열끗 그대로 또는 쌍피로 바꿔서 7점 이상이 되면, 고/스톱보다 먼저 **쌍피 전환 여부를 묻습니다**.
  - 나: 확인 창에 "열끗이면 ○점, 쌍피면 ○점"을 보여 줌
  - AI: 스톱할 때 받을 금액이 큰 쪽을 자동 선택
- 전환하면 피 묶음으로 옮기고, 그 판이 끝날 때까지 되돌릴 수 없습니다. 쌍피로 빼앗길 수 있습니다.
- 거절하면 같은 턴에는 다시 묻지 않습니다.

## 10. 수 추천 (💡 플레이어 도우미)

- 상단 `💡 추천` 버튼으로 켜고 끔(기본 켜짐, 저장). 추천을 써도 점수·보상에는 영향이 없습니다.
- 내 차례에 낼 패(흔들기·폭탄·빈 패 포함)와 바닥 2장 중 고르기에 **1~3위**를 표시합니다.
  - 1위 패에 금색 테두리와 `추천` 표시, 2·3위는 흐리게
  - 1위의 **이유 한 줄**을 바닥 위 안내에 표시(예: "상대 고도리 차단 · 고도리 새·피 1장 획득")
- 흔들기·폭탄·고/스톱·국진 전환 확인 창에도 추천 한 줄을 붙입니다.

### 반드시 지킬 것: 공개된 정보만 사용
- 추천 함수는 실제 게임 상태가 아니라 **공개 정보만 모은 객체**를 받도록 만듭니다.
  - 넣는 것: 내 손패, 바닥, 양쪽 획득 패, 상대 손패·더미 **장수**, 상대가 흔들어 보여 준 패, 고·흔들기 횟수 등
  - 넣지 않는 것: 상대 손패와 더미의 실제 카드
- 모르는 패를 무작위로 상대 손패와 더미에 나눈 가상 배치(32개 정도)로 평가합니다.
- 테스트: 공개 정보는 같고 상대 손패·더미만 바꾼 두 상태에서 추천이 같아야 합니다.

### 계산 방법
- 후보 수마다 가상 배치에서 "내 수 → 더미 뒤집기 → 상대의 응수 한 수"까지 진행해 평가하고 평균이 높은 순으로 고릅니다.
  - 상대 응수는 더미를 보지 않고 바닥과 맞춰 얻는 것만 보고 고르게 합니다(상대가 미래를 아는 것처럼 계산하지 않도록).
- **상대 저지**: 내가 먹는 수와 상대를 막는 수를 한 기준으로 비교합니다.
  - 상대 위협: 족보 2/3, 2광(남은 광이 있을 때), 피 9장·띠 4장·열끗 4장, 총점 5~6점
  - 바닥 2장 중 고를 때도 상대 저지를 함께 봅니다.
  - 상대에게 필요한 족보 패를 내가 쥐고 있으면 함부로 버리지 않습니다.
- **바닥에 남긴 패의 앞으로의 득실**
  - 같은 월 나머지가 모두 내 손이나 이미 먹은 패에 있으면 다음 차례에 확실히 먹으므로 먼저 냅니다(안전한 짝).
  - 같은 월 나머지가 모두 나왔으면 아무도 못 먹으므로 버려도 위험이 없습니다(죽은 패).
  - 그 밖에는 "상대가 그 월을 가지고 있을 확률 × 상대가 얻는 가치"만큼 감점합니다. 쌍피·광을 짝 없이 버리면 위험을 밝힙니다.
- **보너스패 내는 시점**: 상대에게 빼앗을 피가 없으면 아껴 둡니다. 단, 7점에 닿거나 상대가 4점 이상이거나 판이 곧 끝날 수 있으면 지금 냅니다.
- **첫뻑**: 첫 턴의 뻑 가능성은 7점 금액만큼 평가에 반영합니다.
- 검증: 추천대로 두는 쪽과 AI 방식을 같은 판 배분으로 수백 판 대전시켜 승률이 떨어지지 않는지 확인합니다. 한 번 계산은 수십~수백 ms 안이어야 합니다.

## 11. 화면 (UI/UX)

### 배치 (위에서부터)
1. 상단 바: 제목, 레벨, 점당 금액, 전적, 버튼(규칙 · 💡 추천 · 소리 · 처음부터 · 블로그에서는 닫기)
2. 상대: 정보 패널(아래에 손패 뒷면을 작게) · 족보 칩 · 획득 패
3. 바닥: **더미를 가운데** 두고, 새로 놓이는 월은 더미 둘레의 **무작위 방향 빈 칸**에 놓음. 같은 월은 겹쳐 쌓음
4. 나: 정보 패널 · 족보 칩 · 획득 패
5. 내 손패 (가운데 정렬)

### 크기
- 바닥 패·획득 패·내 손패를 **모두 같은 크기**로. 카드 크기는 화면 높이에 맞춰 자동으로 정함.
- 획득 패는 종류별(광·열끗·띠·피)로 묶고, 장수가 많아지면 겹침 간격을 줄여 한 줄에 넣음.

### 정보 패널 (가독성)
- 이름(내 차례면 `차례` 표시) → 보유금 → **큰 점수와 목표(7점, 고 이후엔 다음 점수)까지 막대** → 점수 내역(예: `열끗 1 · 피 4`) → 상태 표시
- 상태 표시: 선, N고, 흔들기, 폭탄, **배수(×2·×4)**, 뻑, **피박 위험·광박 위험**(지금 상대가 스톱하면 실제로 적용될 때만)
- 획득 패 묶음마다 옅은 배경판, 큰 장수 숫자, 점수가 나면 금색 `N점`, 1장 남으면 주황색, 빈 묶음은 점선 자리

### 족보 진행 표시
- 고도리(노랑)·홍단(빨강)·청단(파랑)·초단(초록)·광(주황) 칩
  - 1장 보유: 흐린 점선 칩 / **2장 보유이고 남은 1장이 아직 가능하면 "유력"**: 칩이 깜빡이고 해당 패에 같은 색 테두리 / 완성: 채운 칩 + ✓ / 상대가 1장이라도 가져가 막히면 칩 숨김
- 겹쳐 쌓인 패의 테두리는 **카드 안쪽에만** 그리고, 카드마다 레이어를 분리해 다음 패 위로 선이 지나가지 않게 합니다.

### 조작
- 손패 클릭으로 내기. 바닥과 맞는 패는 금색 테두리, 마우스를 올리면 살짝 올라감.
  - **올라간 패의 원래 자리(아래쪽)도 같은 패로 눌려야 합니다**(클릭 영역을 아래로 늘림). 그렇지 않으면 패 아래쪽을 누를 때 안 나가고 깜빡입니다.
- 바닥 2장 중 고를 때는 고를 수 있는 패가 깜빡입니다.
- 흔들기·폭탄은 확인 창(흔들기/그냥 내기/취소, 폭탄/한 장만 내기/취소).
- 게임 영역 안에서는 **글자 선택과 끌어 놓기를 막습니다**(`user-select: none`, `dragstart`·`selectstart` 차단, 모바일 길게 누르기 메뉴 끔).
- 모바일(폭 720px 이하): 정보 패널과 칩을 한 줄로, 소리·추천 버튼은 아이콘만, 손패 10장이 화면 폭에 들어가게.

## 13. 카드 그림

- 한국식 화투 디자인. 일반 패 48장은 화투 일러스트(.ai) 파일을 SVG로 변환해 썼습니다.
  - Illustrator(.ai) 파일은 PDF 껍데기 안의 `AIPrivateData`에 PostScript로 그림이 들어 있는 경우가 있어, 이것을 직접 해석해 SVG로 바꿨습니다(`tools/*.py`, Python + PyMuPDF).
  - 카드별로 잘라 `public/cards/<번호>.svg`로 저장
- 보너스패와 카드 뒷면, 빈 패는 코드로 그립니다.
- ⚠️ **카드 그림의 저작권을 반드시 확인하세요.** 공개 배포(블로그 게시 포함)는 원저작자의 이용 조건을 따라야 합니다. 직접 그린 그림이나 이용 조건이 분명한 그림을 쓰는 것을 권합니다.

## 14. 블로그 삽입

- `npm run build:blog` → `dist/blog-post.html`: 게임 전체(HTML·CSS·JS·카드 SVG)를 담은 `<script>` 하나. 티스토리 글쓰기 **HTML 모드**에 그대로 붙여 넣습니다.
  - 카드 SVG는 좌표를 상대 좌표로 다시 써서 크기를 줄입니다(약 1.24MB → 0.71MB, 그림은 동일).
  - 문자열 안의 `<`는 `<`로 이스케이프
- 글에는 `맞고 게임 시작` 버튼만 놓이고, 누르면 **화면 전체를 덮는 팝업**으로 열립니다.
  - 팝업은 닫힌 Shadow DOM + iframe `srcdoc` → 블로그 스타일과 서로 영향 없음
  - 열려 있는 동안 뒤쪽 블로그 스크롤 잠금
  - 게임 오른쪽 위 `닫기`(블로그 안에서만 표시)로 닫기. 판이 진행 중이면 기권패 처리를 확인한 뒤 닫음. 대화상자가 떠 있어도 누를 수 있어야 함
- 저장 데이터는 블로그 주소의 localStorage에 남아 다음에 열어도 이어집니다.
- 확인용 `dist/blog-preview.html`: 일부러 스타일을 강하게 준 가짜 블로그 페이지에 글을 넣은 페이지.
- 참고: 티스토리 콘솔의 `429` 오류는 티스토리가 넣는 카카오 오류 수집 서버 요청이 거절된 것으로, 게임과 관계없습니다.

## 15. 검증 기준

AI에게 작업을 맡길 때 아래를 완료 조건으로 함께 요청하세요.
- 규칙 엔진 테스트: 카드 구성, 점수·족보, 배수, 고 보너스, 경제(점당 금액, AI 생성, 나가리 누적), 국진 전환, 보너스패 빼앗기, 2장 폭탄, 뻑 규칙(배분 3장·자뻑·첫뻑)
- 무작위 정책으로 1000판: 모든 프레임에서 카드 50장이 정확히 한 곳에만 있고, 모든 판이 끝나야 함
- 추천: 정보 유출 테스트, 상대 저지·안전한 패·쌍피·보너스패 시점 시나리오 테스트
- 대전 시뮬레이션: AI 대 탐욕 정책, 추천 대 AI 방식 (`npm run sim`, `npm run bench:advice`)
- 브라우저 확인: 데스크톱과 모바일(375×812) 화면에서 실제로 몇 판 진행, 콘솔 오류 없음, 저장 데이터 확인
- 빌드: `npm run build`, `dist/index.html` 파일 직접 열기, `npm run build:blog`
