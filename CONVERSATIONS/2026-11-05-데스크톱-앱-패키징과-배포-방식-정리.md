# 데스크톱 앱 패키징과 배포 방식 정리

## 🙋 질문 또는 요청 사항
지금까지 만들어진 것을 나의 PC나 Mac에서 하나의 앱으로 실행하고 싶어.

## 🤖 Claude 응답
이제 이 게임을 Windows와 Mac에서 하나의 앱으로 실행할 수 있습니다. 게임은 Electron이라는 도구로 앱 창 안에 띄웠고, Windows용 파일은 이 PC에서 만들었습니다. 만든 앱을 실행해 보니 첫 화면(레벨, 보유금, 상대 정보, "게임 시작" 버튼)이 정상으로 나왔습니다. 실제로 한 판을 끝까지 두어 보지는 않았습니다.

**Windows (만들어 둔 파일)**
- [release/Matgo-1.0.0-win-x64.exe](../release/Matgo-1.0.0-win-x64.exe): 설치 파일입니다(약 120MB). 바탕화면과 시작 메뉴에 "맞고" 바로가기가 생깁니다.
- [release/Matgo-1.0.0-portable.exe](../release/Matgo-1.0.0-portable.exe): 설치 없이 더블클릭하면 바로 실행되는 파일입니다.

**Mac**
Mac용 설치 파일(.dmg)은 Mac에서만 만들 수 있습니다. Mac에 이 프로젝트를 받아서 아래 두 명령을 차례로 실행하면 `release/` 폴더에 dmg 파일이 생깁니다. Intel과 Apple Silicon Mac 모두에서 돌아갑니다.

```bash
npm install
```

```bash
npm run dist:mac
```

**자주 쓸 명령**
- `npm run app`: 빌드한 뒤 앱 창으로 바로 실행합니다.
- `npm run dist:win`: Windows용 파일을 다시 만듭니다.

**알아 둘 점**
- **첫 실행 경고:** 코드 서명이 없어서 처음 실행할 때 경고가 뜹니다. Windows에서는 "추가 정보 → 실행"을, Mac에서는 "우클릭 → 열기"를 누르면 됩니다.
- **저장 데이터:** 앱은 저장 공간을 따로 써서, 브라우저에서 하던 레벨과 보유금은 이어지지 않고 처음부터 시작합니다.
- **파일 크기:** 앱 안에 Chromium 브라우저가 통째로 들어가서 파일이 큽니다. 게임 코드는 바뀌지 않았습니다.

**바뀐 파일**
- [electron/main.cjs](../electron/main.cjs): 앱 창을 띄우는 코드입니다. 앱은 하나만 실행되고, 외부 링크는 기본 브라우저로 열립니다.
- [package.json](../package.json): 위 명령들과 설치 파일 설정을 추가했습니다.
- [build/icon.png](../build/icon.png): 송학 광 카드로 만든 앱 아이콘입니다. [tools/make-icon.cjs](../tools/make-icon.cjs)로 다시 만들 수 있습니다.
- [README.md](../README.md): 데스크톱 앱 섹션을 추가했습니다.
- `.gitignore`: 빌드 결과가 담기는 `release/` 폴더를 커밋에서 뺐습니다.

## 🙋 질문 또는 요청 사항
PC용 앱을 실행하여 상태가 어디에 저장되지?

## 🤖 Claude 응답
PC 앱의 상태는 브라우저 저장소(localStorage)에 저장되고, 그 파일은 아래 폴더 안에 있습니다.

```
C:\Users\pig48\AppData\Roaming\gostop\Local Storage\leveldb\
```

- **폴더 이름:** 앱 이름이 "맞고"인데도 폴더는 `gostop`입니다. Electron이 `package.json`의 `"name": "gostop"`으로 폴더 이름을 정하기 때문입니다. 실제로 이 PC에서 `%APPDATA%\gostop`이 만들어진 것을 확인했고, `맞고`나 `Matgo` 폴더는 없습니다.
- **저장되는 값:** 게임 코드가 쓰는 키는 세 개입니다.
  - `gostop-save-v1`: 레벨, 보유금, 전적, 상대 AI ([economy.ts:8](../src/engine/economy.ts))
  - `gostop-advice`: 💡 추천을 켰는지 껐는지 ([app.ts:33](../src/ui/app.ts))
  - `gostop-muted`: 소리를 켰는지 껐는지 ([sound.ts:7](../src/ui/sound.ts))
- **지금 상태:** 아직 아무 값도 저장되지 않았습니다. 확인할 때 앱을 열기만 하고 게임을 시작하지 않았기 때문입니다.
- **함께 쓰는 실행 방식:** 설치 버전, 포터블 버전, `npm run app` 모두 같은 폴더를 씁니다. 그래서 어느 쪽으로 실행해도 진행 상황이 이어집니다.
- **브라우저와는 별개:** 브라우저에서 하던 진행 상황과는 공유되지 않습니다.
- **삭제 시:** 앱을 제거해도 이 폴더는 남습니다. 완전히 처음부터 하려면 게임 안의 "처음부터" 버튼을 쓰거나, 앱을 끈 뒤 `%APPDATA%\gostop` 폴더를 지우면 됩니다.

참고로 Mac에서는 `~/Library/Application Support/gostop/`에 저장됩니다.

## 🙋 질문 또는 요청 사항
release 폴더에 Matgo-1.0.0-portable.exe를 실행했을 때, 화면 출력이 매우 느린데, 이유가 뭐지?

## 🤖 Claude 응답
느린 것은 게임 화면을 그리는 속도가 아니라 앱이 처음 뜨기까지의 시간입니다. 포터블 실행 파일은 실행할 때마다 압축을 푸는 방식이라 시작에 십몇 초가 걸립니다. 같은 PC에서 재 보니 이렇습니다.

| 실행 방식 | 앱이 뜨기까지 |
|---|---|
| `Matgo-1.0.0-portable.exe` | 약 **14초** |
| `win-unpacked\Matgo.exe` (압축이 이미 풀린 앱) | 약 **0.3초** |

**원인**
- 포터블 exe는 약 110MB의 압축 파일입니다. 실행할 때마다 안에 든 앱 전체(약 360MB)를 `%LOCALAPPDATA%\Temp\<임의 이름>\` 폴더에 풀고 나서야 앱을 시작합니다.
- 실제로 실행 중인 화면의 주소가 `C:\Users\pig48\AppData\Local\Temp\3Lfd7ly...\resources\app.asar\...`였습니다.
- 앱을 종료하면 이 임시 폴더를 지우기 때문에, 다음 실행 때 다시 처음부터 풉니다.

**게임 화면 자체는 정상입니다**
- 포터블로 띄운 앱 안에서 측정했고, 그래픽카드(GTX 1660)를 쓰고 있었습니다.
- 대기 화면에서 초당 약 166프레임, 패를 나눈 직후에 약 150프레임이 나왔습니다.
- 패를 한 장 낼 때 화면이 잠깐 멈추는 구간은 84ms짜리 한 번뿐이었습니다.

**해결 방법**
1. **설치 파일 사용 (권장):** `Matgo-1.0.0-win-x64.exe`로 한 번 설치하면 압축이 풀린 상태로 남아서 매번 바로 뜹니다.
2. **설치 없이 쓰려면:** `release\win-unpacked` 폴더를 통째로 복사해 두고 그 안의 `Matgo.exe`를 실행하면 됩니다.
3. **빌드 설정 변경:** 포터블 exe 대신, 압축을 한 번만 풀어 두고 쓰는 ZIP 파일이 만들어지도록 빌드 설정을 바꿀 수 있습니다.

## 🙋 질문 또는 요청 사항
Yes, switch to ZIP

## 🤖 Claude 응답
포터블 exe를 없애고, 설치 없이 쓰는 방식을 ZIP 파일로 바꿨습니다. 압축을 한 번 풀어 두면 그다음부터는 바로 뜹니다.

**새로 만든 파일** (`release/`)
- [Matgo-1.0.0-win-x64.exe](../release/Matgo-1.0.0-win-x64.exe): 설치 파일, 약 120MB
- [Matgo-1.0.0-win-x64.zip](../release/Matgo-1.0.0-win-x64.zip): 원하는 폴더에 풀고 안의 `Matgo.exe`를 실행합니다. 약 150MB입니다.

**시작 시간** (ZIP을 풀어서 두 번 실행해 봄)

| 실행 | 앱이 뜨기까지 |
|---|---|
| 이전 포터블 exe | 약 14초 (매번) |
| ZIP을 푼 뒤 첫 실행 | 약 7.8초 |
| ZIP을 푼 뒤 두 번째 실행 | 약 **0.3초** |

첫 실행만 느린 이유는 Windows Defender가 새로 생긴 파일을 검사하기 때문으로 보입니다. 확실히 확인한 것은 아니고, 두 번째부터는 빨라졌습니다. 게임 화면은 두 번 모두 초당 약 166프레임으로 그려졌고, 그래픽카드도 쓰고 있었습니다.

**바뀐 파일**
- [package.json](../package.json): Windows 빌드 결과를 "설치 파일 + 포터블 exe"에서 "설치 파일 + ZIP"으로 바꿨습니다.
- [README.md](../README.md): 바뀐 빌드 결과와 ZIP 사용법, 포터블을 쓰지 않는 이유를 적었습니다.

이 변경은 아직 커밋하지 않았습니다.
